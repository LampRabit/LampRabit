# Decisions: Databases

The user's decisions and the reasons behind them. Don't reverse one without asking the user; when the user changes one, edit it here with the date.

- **MySQL** (Oracle) runs next to MariaDB on port 3307 (`ports.mysqlServer`; `ports.mysql` is MariaDB's, the name predates MySQL). Versions come from docker-library's `versions.json`, archives from cdn.mysql.com (Linux: the `-minimal` tarball), checked by MD5. Each release line has its own data folder (`data/mysql-8.4`…) because MySQL can't downgrade. `mysql_native_password=ON` is written only for 8.x (9.0 removed it). On Linux, `configs::mysql_libraries` links `libaio.so.1t64` to `libaio.so.1` (Ubuntu 24.04+) and otherwise names the packages to install.
- **Default database** (`Settings.default_database`, MariaDB or MySQL; falls back to whichever is installed): drives the `mysql`/`mysqldump`/`mysqladmin` shims (`mariadb*` always mean MariaDB), new projects' databases and `.env`, and the order of servers in phpMyAdmin (`?server=N`) and Adminer (a server picker via `loginFormField`). Tools connect through `etc/<db>/client.cnf` (host, port, user), which exists before the server first starts.
- **More databases** (2026-11-01): PostgreSQL (theseus-rs builds; data per major `data/postgres-<major>`; a `root` superuser is added after every start so framework defaults work) and MongoDB (MongoDB's `full.json`; Linux builds per distro via `mongodb_target_for`; data per major). `config::Database` stays the MySQL family (it drives the `mysql` shims); project creation uses `templates::DbEngine`, and templates list the engines they support (`engines:`). Backups live in `<root>/backups/` (kept on uninstall). PostgreSQL's tools: Adminer, phpPgAdmin (PHP 8 fork) and pgAdmin (a PyPI wheel in its own venv, needing LampRabit's Python 3.10–3.14).
- **PostgreSQL elevated on Windows** (2026-11-12): it refuses administrator rights (GitHub's runners, UAC off, "Run as administrator"); then `--pg-elevated` runs it through `pg_ctl` and stands in for it (log, exit) so the supervisor works unchanged.
- **Default app per database** (the user's choice, 2026-11-24, refined the same day): **KarotX is the default for every database**; the user can pick another web tool per database. The choice is shown **on the Services page**, on every database's page ("Opens in": every app that can open it, uninstalled ones link to their page) and on every database client's page ("Default app for": a switch per database it can open), and also in Settings → Databases. It's a real setting (`Settings.db_clients`, database id → tool id, saved at once by `set_db_client`; absent means KarotX), not a device preference, so every page reads the same value. Which clients open which database: `DB_CLIENTS` in `lib/tools.ts` (MariaDB/MySQL: KarotX, phpMyAdmin, Adminer; PostgreSQL: KarotX, pgAdmin, phpPgAdmin, Adminer; MongoDB: KarotX; Redis: KarotX, phpRedisAdmin). Home's ⋯ menu opens the others without changing the default. Desktop clients (DBeaver, TablePlus…) were not asked for.
- **PostgreSQL extensions** (the user asked, 2026-11-26): a panel on PostgreSQL's Services page, per database, through psql as `postgres`: on = `CREATE EXTENSION IF NOT EXISTS … CASCADE`, off = `DROP EXTENSION` without cascade (PostgreSQL's refusal says what depends on it), Update when the server's version is newer. Only what the installed server ships is listed (no downloads of PostGIS or pgvector yet). Other services were checked: PHP already has its dialog; MariaDB/MySQL plugins, Redis modules, MongoDB and the rest got nothing.
