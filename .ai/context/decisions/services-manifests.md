# Decisions: Pluggable services (service manifests)

The user's decisions of 2026-11-15, for phase 27 ([../../plans/active/phase-27-pluggable-services.md](../../plans/active/phase-27-pluggable-services.md)). Format reference for service authors: [docs/services.md](../../../docs/services.md).

- **Goal:** make LampRabit extensible by the community without app releases. The built-in services ship with the app; anyone can write a service as YAML and submit it.
- **Every service is a YAML manifest** (`src-tauri/services/<id>.yaml`, engine in `manifest.rs`). **All** built-in services move to YAML. Core and hybrid services (web servers, MariaDB/MySQL data setup, PostgreSQL, pgAdmin, Tomcat) keep named `builtin` hooks for what can't be declarative (vhosts, PHP pools, data init); only built-in manifests may use them.
- **Manifests find new versions themselves** (GitHub latest / newest per major, npm…, with a checksum required), so a software release needs no registry PR. A manifest's `revision` changes only when how the service installs or runs changes.
- **Service options live in the manifest's `settings:`** and show up automatically in that service's Settings card on the Services page (the user's request, 2026-11-15).
- **Registry:** the repository `LampRabit/Services`, one PR per `service.yaml` + icon + README, reviewed and merged by the user. The website's marketplace page and the app read its signed `index.json`.
- **Signing:** the user is the only signer of the registry index (ed25519/minisign; the private key in a repository secret, the public key in the app).
- **Safety rules for manifests:** declarative only (no shell), checksums mandatory, paths inside the service's own folders, programs inside the install, 127.0.0.1 only, ports above 1023 for community services. New capability goes into the format, not into Rust special cases.
- **No service depends on hard-coded code** (the user's choice, 2026-11-21): the format must describe every service completely, so built-in services use only features a community manifest could use. The one exception is the **site engine** (virtual hosts, PHP pools, HTTPS certificates, the hosts file, Tomcat's per-project hosts): it stays in Rust as the core of LampRabit, exposed as one documented capability (`kind: web-server`) instead of per-server hooks. A web server's downloads, ports, start/stop and settings are YAML like any service.
- **The marketplace ships later** (2026-11-21): step D (registry repo, signed index, Community section, website page) waits; step E (the wider format) and the leftovers of B/C come first. Commit to `dev-1.0`, no pull request until the user asks.
- **KarotX is first-party** (the user's choices, 2026-11-21): KarotX (github.com/LampRabit/KarotX), the user's own database client, ships with LampRabit as a **bundled** manifest (`src-tauri/services/karotx.yaml`, `manifest::BUNDLED`: embedded, community rules, no enum variant, not removable) and comes **before** the other database clients: first in its Services group and in Essentials, first in each database's `suggests`, the default client in Home's database rows and the project card, recommended by the setup guide instead of phpMyAdmin. Every local database is listed in it through a **services file** LampRabit keeps (`connects`, `clients.rs`): the user's integration spec of 2026-11-22 replaced the earlier sync through KarotX's HTTP API. The user asked that **every local database** be available in KarotX (2026-11-22): every installed database service, running or stopped (MariaDB, MySQL, PostgreSQL, MongoDB, Redis, Memcached, ClickHouse on its native port, Neo4j on Bolt), and every SQLite file in the projects.
- **Services that need other services say so** (the user, 2026-11-24): what isn't installed is offered by Related services (Install); what is installed but stopped shows as a notice with Start on the service's page (`NeedsRunning.tsx`) and, while the service runs, in Home's Needs attention ("pgAdmin needs PostgreSQL running"). The rule is `lib/dependencies.ts`: a manifest's `needs` that are services must run; a database client needs one of its databases running.
- **Later and separate:** "tools and plugins", extensions like a browser's. They are not services.
