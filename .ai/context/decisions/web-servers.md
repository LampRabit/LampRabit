# Decisions: Web servers and ports

The user's decisions and the reasons behind them. Don't reverse one without asking the user; when the user changes one, edit it here with the date.

- **Ports below 1024 on Linux**: the web server start asks once (pkexec) to write `/etc/sysctl.d/50-lamprabit.conf` lowering `ip_unprivileged_port_start`. `port_free` treats EACCES as free.
- **Several web servers** (2026-11-01): `Settings.web_servers` is an ordered list (Apache, Nginx, Caddy; FrankenPHP and Tomcat next). The first is primary: main ports, localhost, the tools; each other server has its own pair in `Ports` (`apache_http`, `nginx_http`, `caddy_http`…). The pre-0.3 `webServer = "both"` is converted in `Settings::normalize`. Loop over `ServiceKind::WEB`/`Server::ALL`, never a hard-coded Apache/Nginx pair. Caddy: generated `etc/caddy/Caddyfile` (`sites::render_caddy`, `auto_https off`, our CA, `php_fastcgi` to the pools), `caddy validate` before start, `caddy reload`/`stop` through the admin API (`ports.caddyAdmin`), state in `tmp/caddy` (XDG vars). FrankenPHP reuses `render_caddy` (`php_server`, its own PHP: no pools, no per-site PHP version, ini in `etc/frankenphp/conf.d`). Tomcat isn't a `Server`: Java projects (`Language::Java`) with a web app get a `<Host>` in `etc/tomcat/conf/server.xml` and their domain proxies to `ports.tomcatHttp` with the Host header kept; Tomcat runs as `java … Bootstrap start` on the active Java (`configs::tomcat_java` checks the version).
